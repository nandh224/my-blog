# 지침: 2048 게임 - Review 단계

너는 이 저장소(my-blog)의 Review 서브에이전트다. Build 단계와는 별개의 독립적인 검증을 수행하라
(Build 서브에이전트가 스스로 한 검증을 그대로 믿지 말고 직접 확인할 것).

## 배경

`/apps/2048/`에 순수 HTML/CSS/JS로 2048 게임이 구현되어 있다:
- `index.html`, `style.css`, `game.js`
- 계획 문서: `/apps/2048/spec.md` (요구사항과 설계가 여기 정리되어 있다)

## 네 임무

1. `spec.md`를 읽고 요구사항을 파악한다.
2. `index.html`, `style.css`, `game.js`를 꼼꼼히 읽고 코드를 검토한다:
   - spec.md의 설계(자료구조, 주요 함수, 조작 방식, localStorage 사용 범위 등)와 실제 구현이
     일치하는지
   - 버그 가능성이 있는 부분(예: 4방향 회전/전치 로직의 인덱스 오류, 병합 이중 처리, 경계값 처리,
     게임 오버/승리 판정 로직 오류, localStorage 키 접근 시 예외 등)
   - 방향키 입력 시 페이지 스크롤 방지(`preventDefault`) 여부
   - 모바일 터치 스와이프 로직이 키보드 이동 로직과 제대로 공유되는지
   - 라이트/다크 모드 CSS 변수가 누락 없이 정의되어 있는지, 반응형이 실제로 동작할지
   - 접근성이나 명백한 오탈자, 깨진 링크(예: 블로그로 돌아가는 링크 경로) 등
3. **가능하다면 실제로 브라우저에서 동작을 확인한다.**
   - `apps/2048/index.html`을 브라우저에서 열어(로컬 파일 경로로 직접 열어도 되고, 필요하면
     간단한 정적 서버를 그 폴더에서 임시로 띄워도 된다) 다음을 확인:
     - 페이지가 정상 로드되고 4x4 보드와 점수판이 보이는지
     - 방향키로 타일이 이동/병합되는지, 점수가 올라가는지
     - 새 게임 버튼이 동작하는지
     - 콘솔에 JS 에러가 없는지
   - 브라우저 자동화 도구를 쓸 수 없는 환경이라면, 대신 Node.js로 `game.js`의 순수 로직 함수들
     (`slideAndMergeLine`, `move` 등 DOM에 의존하지 않는 부분)을 발췌해 별도 테스트 스크립트로
     실행해보는 방식으로 로직을 검증하라. 이 경우 무엇을 어떻게 검증했는지 review.md에 명시할 것.
4. 발견한 문제를 심각도와 함께 정리하고, **간단히 고칠 수 있는 문제라면 네가 직접 수정한다**
   (파일: `apps/2048/index.html`, `apps/2048/style.css`, `apps/2048/game.js`만 수정 가능).
   구조적으로 큰 재작업이 필요한 문제라면 고치지 말고 review.md에 남겨서 보고만 하라.
5. 검토 결과를 `/apps/2048/review.md`에 작성한다. 포함할 내용:
   - 검증 방법(브라우저 실행 여부, 어떤 시나리오를 확인했는지)
   - 발견한 문제 목록 (심각도: 치명적/경미/제안)
   - 수정한 문제와 수정 내용
   - 남아있는(수정하지 않은) 이슈가 있다면 이유와 함께 명시
   - 최종 결론: 이 게임이 정상 동작한다고 판단하는지

## 제약

- 수정 가능한 파일: `apps/2048/index.html`, `apps/2048/style.css`, `apps/2048/game.js`,
  그리고 결과 보고서 `apps/2048/review.md`.
- 그 외 어떤 파일도 건드리지 마라 (`spec.md`, 지침 파일들, 블로그 다른 파일 포함).
- 요구사항에 없는 새 기능을 추가하지 마라. 버그 수정과 명백한 오류 교정만 한다.

## 완료 후

review.md에 무엇을 적었는지, 수정한 문제가 있다면 무엇인지 요약해서 보고하라.
