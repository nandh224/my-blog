# 지침: 2048 게임 - Plan 단계

너는 이 저장소(my-blog)의 Plan 서브에이전트다. 아래 범위 내에서만 작업하라.

## 배경

my-blog는 마크다운 블로그 + 미니 웹앱 포트폴리오 프로젝트다. 프레임워크 없이 순수 HTML/CSS/JS만
사용한다 (CDN 라이브러리는 허용). 이번에 추가할 웹앱은 **2048 게임**이다.

## 요구사항 (사용자 요청 원문)

- 방향키(화살표 키)로 숫자 타일을 밀어서 합치는 퍼즐 게임
- 점수판(현재 점수, 가능하면 최고 점수) 포함
- 모바일에서도 사용 가능해야 함 (터치 스와이프 등 고려)

## 네 임무

**코드를 작성하지 마라.** 오직 계획만 세우고 문서로 정리한다.

1. 저장소 구조를 파악한다. 특히 `/apps/` 폴더가 어떻게 구성될 예정인지,
   블로그 메인 페이지(`src/templates.js`, `src/build.js`, `dist/index.html`)가
   어떻게 빌드되는지 살펴봐서 나중에 Embed 단계에서 무엇을 건드려야 할지 파악한다
   (단, 이번 단계에서 파일을 수정하지는 마라).
2. 2048 게임을 위한 계획을 세운다:
   - 파일 구조: `/apps/2048/` 안에 어떤 파일들을 만들 것인지 (예: index.html, style.css, game.js 등)
   - 게임 로직 설계: 4x4 그리드, 타일 이동/병합 규칙, 랜덤 타일 생성, 게임 오버 판정, 승리(2048 타일) 판정
   - 조작: 방향키 입력 처리 + 모바일 터치 스와이프 처리
   - 점수판: 현재 점수 UI, localStorage를 이용한 최고 점수 저장 여부(제안만 하고 과설계는 피할 것)
   - 스타일: 블로그의 라이트/다크 모드, 반응형 원칙과 어울리는 간단한 디자인 (블로그 CSS를 그대로
     가져다 쓸 필요는 없음 — 앱은 자체 완결적이어야 함)
   - 외부 라이브러리 필요 여부 (원칙적으로 최소화, 순수 JS로 충분한지 검토)
3. 계획을 `/apps/2048/spec.md` 파일로 작성한다. 다음을 포함할 것:
   - 개요
   - 파일 구조 (트리 형태)
   - 각 파일의 역할
   - 게임 로직 핵심 설계 (자료구조, 주요 함수)
   - UI/UX 및 조작 방식
   - Embed 단계에서 블로그 메인 페이지의 어느 파일을 어떻게 수정해야 하는지에 대한 메모

## 제약

- `/apps/2048/spec.md` 파일만 생성/수정한다. 그 외 어떤 파일도 만들거나 수정하지 마라.
- 실제 게임 코드(HTML/CSS/JS)는 작성하지 마라. 이번 단계는 계획 수립까지만.
- 과도한 기능(리더보드 서버, 계정 시스템 등)을 제안하지 마라. 요청 범위(방향키 조작, 타일 병합,
  점수판, 모바일 대응)에 충실할 것.

## 완료 후

작업을 마치면 `/apps/2048/spec.md`가 작성되었음을 요약해서 보고하라.
