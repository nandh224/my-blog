# 지침: 타이머/스톱워치 - Review 단계

너는 이 저장소(my-blog)의 Review 서브에이전트다. Build 단계와는 별개의 독립적인 검증을
수행하라 (Build 서브에이전트가 스스로 한 검증을 그대로 믿지 말고 직접 확인할 것).

## 배경

`/apps/timer/`에 순수 HTML/CSS/JS로 카운트다운 타이머/스톱워치 앱이 구현되어 있다:
- `index.html`, `style.css`, `timer.js`
- 계획 문서: `/apps/timer/spec.md` (요구사항과 설계가 여기 정리되어 있다)

## 네 임무

1. `spec.md`를 읽고 요구사항을 파악한다.
2. `index.html`, `style.css`, `timer.js`를 꼼꼼히 읽고 코드를 검토한다:
   - spec.md의 설계(자료구조, 주요 함수, 타이밍 정확도 원칙, 모드 전환 정책 등)와 실제
     구현이 일치하는지
   - 버그 가능성이 있는 부분: 카운트다운/스톱워치의 시간 계산이 `Date.now()` 기준으로
     정확히 재계산되는지(누적 오차 없는지), 모드 전환 시 자동 일시정지가 상태를 올바르게
     보존하는지, 카운트다운 완료 판정과 중복 알림 방지(`finished` 플래그) 로직, 리셋 후
     재시작이 올바르게 동작하는지
   - `[hidden]` 속성과 CSS `display` 규칙 간의 캐스케이드 충돌 여부 (2048 앱에서 실제로
     발생했던 버그 패턴이니 유사한 곳이 없는지 확인)
   - 모바일 터치 입력 시 페이지 스크롤 방지 여부, 숫자 입력 필드의 `inputmode` 등
   - 라이트/다크 모드 CSS 변수가 누락 없이 정의되어 있는지, 반응형이 실제로 동작할지
   - 사용법 안내 문구가 실제로 존재하는지
   - 접근성이나 명백한 오탈자, 깨진 링크(블로그로 돌아가는 링크 경로) 등
3. **가능하다면 실제로 브라우저에서 동작을 확인한다.**
   - `apps/timer/index.html`을 브라우저에서 열어(로컬 파일 경로로 직접 열어도 되고, 필요
     하면 그 폴더에서 임시 정적 서버를 띄워도 된다) 다음을 확인:
     - 페이지가 정상 로드되고 두 모드 탭, 시간 표시, 조작 버튼이 보이는지
     - 카운트다운 시작/일시정지/리셋, 스톱워치 시작/일시정지/리셋이 실제로 동작하는지
     - 짧은 시간(예: 3초)으로 카운트다운을 걸어 실제로 완료 알림(비프음/시각 효과)이
       발생하는지
     - 모드 탭 전환 시 실행 중이던 타이머가 자동으로 일시정지되는지
     - 콘솔에 JS 에러가 없는지
   - 브라우저 자동화 도구를 쓸 수 없는 환경이라면, 대신 Node.js로 `timer.js`의 DOM에
     의존하지 않는 순수 로직 함수들(시간 포맷팅, 남은/경과 시간 계산 함수 등)을 발췌해
     별도 테스트 스크립트로 실행해보는 방식으로 로직을 검증하라. 이 테스트 스크립트는
     검증용 임시 산출물이므로 저장소 밖(스크래치패드 등)에 작성하고 `/apps/timer/` 안에는
     남기지 않는다. 무엇을 어떻게 검증했는지 review.md에 명시할 것.
4. 발견한 문제를 심각도(치명적/경미/제안)와 함께 정리하고, **간단히 고칠 수 있는 문제라면
   네가 직접 수정한다** (수정 가능 파일: `apps/timer/index.html`, `apps/timer/style.css`,
   `apps/timer/timer.js`만). 구조적으로 큰 재작업이 필요한 문제라면 고치지 말고 review.md에
   남겨서 보고만 하라.
5. 검토 결과를 `/apps/timer/review.md`에 작성한다. 포함할 내용:
   - 검증 방법(브라우저 실행 여부, 어떤 시나리오를 확인했는지)
   - 발견한 문제 목록 (심각도 포함)
   - 수정한 문제와 수정 내용
   - 남아있는(수정하지 않은) 이슈가 있다면 이유와 함께 명시
   - 최종 결론: 이 앱이 정상 동작한다고 판단하는지

## 제약

- 수정 가능한 파일: `apps/timer/index.html`, `apps/timer/style.css`, `apps/timer/timer.js`,
  그리고 결과 보고서 `apps/timer/review.md`.
- 그 외 어떤 파일도 건드리지 마라 (`spec.md`, 지침 파일들, 다른 `/apps/*/`, 블로그 다른
  파일 포함).
- 요구사항에 없는 새 기능을 추가하지 마라. 버그 수정과 명백한 오류 교정만 한다.

## 완료 후

review.md에 무엇을 적었는지, 수정한 문제가 있다면 무엇인지 요약해서 보고하라.
