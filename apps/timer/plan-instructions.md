# 지침: 타이머/스톱워치 - Plan 단계

너는 이 저장소(my-blog)의 Plan 서브에이전트다. 아래 범위 내에서만 작업하라.

## 배경

my-blog는 마크다운 블로그 + 미니 웹앱 포트폴리오 프로젝트다. 프레임워크 없이 순수
HTML/CSS/JS만 사용한다 (CDN 라이브러리는 허용). 이미 `/apps/2048/`, `/apps/pixel-art/`에
같은 방식으로 구현된 앱이 있으니 스타일/패턴 참고용으로 읽어보라(그대로 베끼지는 말 것,
수정 금지). 이번에 추가할 웹앱은 **타이머/스톱워치**다.

## 요구사항 (사용자 요청 원문)

- 카운트다운 타이머와 스톱워치 두 가지 모드
- 시작/일시정지/리셋 조작
- 모바일에서도 사용 가능해야 함

## 네 임무

**코드를 작성하지 마라.** 오직 계획만 세우고 문서로 정리한다.

1. 저장소 구조를 파악한다. 특히 `/apps/` 폴더가 어떻게 구성되어 있는지, `src/build.js`가
   `/apps/`를 `dist/apps/`로 어떻게 복사하는지, `src/templates.js`가 블로그 메인 페이지에
   각 앱의 카드를 어떻게 렌더링하는지 살펴봐서 나중에 Embed 단계에서 무엇이 필요한지 파악한다
   (단, 이번 단계에서 파일을 수정하지는 마라).
2. 타이머/스톱워치를 위한 계획을 세운다:
   - 파일 구조: `/apps/timer/` 안에 어떤 파일들을 만들 것인지
   - 핵심 로직 설계: 자료구조, 주요 함수 (카운트다운 타이머와 스톱워치 각각의 시간 계산 방식,
     `setInterval`/`requestAnimationFrame` 등 타이밍 정확도를 어떻게 확보할지 포함)
   - 조작 방식: 데스크톱 입력 + 모바일 터치 대응
   - 스타일: 라이트/다크 모드, 반응형. `src/styles.css`의 팔레트(`--bg`, `--text`,
     `--text-secondary`, `--link`, `--border`, `--code-bg`)와 다크모드 대응 방식(기본값 +
     `prefers-color-scheme: dark` + `data-theme` 속성 오버라이드)을 참고해서 앱 자체 CSS에
     동일한 값으로 변수를 다시 정의할 것을 계획에 명시한다 (앱은 자체완결이므로 `styles.css`를
     직접 import하지 않는다)
   - 사용법 안내 문구를 화면 어디에 어떻게 넣을지
   - 외부 라이브러리 필요 여부 (원칙적으로 최소화, 순수 JS로 충분한지 검토)
3. 계획을 `/apps/timer/spec.md` 파일로 작성한다. 다음을 포함할 것:
   - 개요
   - 파일 구조 (트리 형태)
   - 각 파일의 역할
   - 핵심 로직 설계 (자료구조, 주요 함수)
   - UI/UX 및 조작 방식
   - Embed 단계 메모: `src/build.js`의 `apps` 배열에 `{ name, path, description }` 항목을
     추가하면 `src/templates.js`의 `appsSection()`이 카드(제목/설명/iframe 미리보기)를 자동
     렌더링하는 구조이므로, 보통 `build.js`/`templates.js` 자체를 고칠 필요는 없다 — 실제로
     그런지 저장소를 확인해서 메모에 적을 것

## 제약

- `/apps/timer/spec.md` 파일만 생성/수정한다. 그 외 어떤 파일도 만들거나 수정하지 마라
  (다른 `/apps/*/`는 참고용으로 읽기만 하고 절대 수정하지 마라).
- 실제 코드(HTML/CSS/JS)는 작성하지 마라. 이번 단계는 계획 수립까지만.
- 요청 범위(카운트다운 타이머 + 스톱워치, 시작/일시정지/리셋, 모바일 대응)를 벗어난 과도한
  기능(알람음 커스터마이징, 여러 타이머 동시 실행, 저장된 프리셋 등)을 제안하지 마라.

## 완료 후

작업을 마치면 `/apps/timer/spec.md`가 작성되었음을 요약해서 보고하라.
