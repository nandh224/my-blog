# 지침: 타이머/스톱워치 - Build 단계

너는 이 저장소(my-blog)의 Build 서브에이전트다. 아래 범위 내에서만 작업하라.

## 배경

my-blog는 마크다운 블로그 + 미니 웹앱 포트폴리오 프로젝트다. 프레임워크 없이 순수
HTML/CSS/JS만 사용한다. Plan 단계에서 계획 문서 `/apps/timer/spec.md`가 이미 작성되었다.
먼저 이 문서를 읽고 그 내용을 그대로 구현하라. 참고로 `/apps/2048/`, `/apps/pixel-art/`에
동일한 방식으로 만든 앱이 있으니 스타일/패턴 참고용으로 읽어봐도 좋다(단, 수정하지는 마라).

## 네 임무

`spec.md`의 계획에 따라 `/apps/timer/` 안에 실제로 구현한다:

- `/apps/timer/index.html`
- `/apps/timer/style.css`
- `/apps/timer/timer.js`

spec.md 5절(핵심 로직 설계)의 자료구조·주요 함수·타이밍 정확도 원칙, 6절(UI/UX)의 모드
전환 정책·모바일 대응·사용법 안내 문구를 충실히 따른다. 특히:

- 카운트다운/스톱워치 모두 `Date.now()` 기준 타임스탬프로 매 틱마다 재계산 (setInterval
  오차 누적 방지)
- 모드 탭 전환 시 실행 중인 타이머 자동 일시정지 (상태는 보존)
- 시작/일시정지 토글 버튼 + 리셋 버튼
- 카운트다운 완료 시 Web Audio API 비프음 + 시각 효과
- 라이트/다크 모드 CSS 변수(spec.md 4절에 정리된 `src/styles.css`와 동일한 값), 모바일
  반응형, 44px 이상 탭 영역
- 사용법 안내 문구 포함 (필수)

spec.md 7절 "범위 밖"에 명시된 항목(알람 커스터마이징, 다중 타이머, 프리셋, 진행상태
저장/복원, 랩타임, 브라우저 알림/진동 연동)은 구현하지 마라.

## 제약 (중요)

- **`/apps/timer/` 폴더 안의 파일만 생성/수정한다.** (`index.html`, `style.css`, `timer.js`)
- `/apps/timer/spec.md`, `plan-instructions.md`, `build-instructions.md`는 수정하지 마라.
- 이 폴더 밖의 어떤 파일도 건드리지 마라 — `src/build.js`, `src/templates.js`, `CLAUDE.md`,
  다른 `/apps/*/`, 블로그의 다른 어떤 파일도 포함된다. (블로그 메인 페이지 연동은 별도의
  Embed 단계에서 처리한다.)
- 프레임워크(React/Vue 등) 사용 금지. 순수 HTML/CSS/JS만 사용.
- 불필요한 추상화, 설정 옵션, 과도한 주석을 추가하지 마라. 주석은 자명하지 않은 이유(WHY)가
  있을 때만 최소한으로 작성한다.

## 완료 후

무엇을 만들었는지, spec.md의 계획과 다르게 구현한 부분이 있다면(있어서는 안 되지만 불가피한
경우) 그 이유를 요약해서 보고하라.
