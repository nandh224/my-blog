# 지침: 픽셀 아트 에디터 - Plan 단계

너는 이 저장소(my-blog)의 Plan 서브에이전트다. 아래 범위 내에서만 작업하라.

## 배경

my-blog는 마크다운 블로그 + 미니 웹앱 포트폴리오 프로젝트다. 프레임워크 없이 순수 HTML/CSS/JS만
사용한다 (CDN 라이브러리는 허용). 이미 `/apps/2048/`에 2048 게임이 같은 방식으로 구현되어 있고,
`src/build.js`가 `/apps/`를 `dist/apps/`로 복사하며, `src/templates.js`가 블로그 메인 페이지에
각 앱의 카드(제목/설명/iframe 미리보기)를 렌더링한다. 이번에 추가할 앱은 **픽셀 아트 에디터**다.

## 요구사항 (사용자 요청 원문)

- 16x16 격자에 도트(픽셀)를 찍어서 그림을 그리는 에디터
- 완성한 그림을 PNG 파일로 저장(다운로드)할 수 있어야 함
- 색상 팔레트 포함 (그릴 색상을 선택)
- (프로젝트 공통 요구사항) 모바일에서도 사용 가능해야 함

## 참고 — 기존 앱(2048) 구조에서 배울 점

`/apps/2048/spec.md`, `/apps/2048/index.html`, `/apps/2048/style.css`, `/apps/2048/game.js`를
먼저 훑어보고, 이 저장소에서 미니 웹앱을 어떤 스타일/패턴으로 만들어왔는지(자체 완결적 CSS 변수
기반 다크모드, 블로그로 돌아가는 링크, 파일 구성 방식 등) 참고하라. 다만 그대로 베낄 필요는 없고,
픽셀 아트 에디터에 맞게 계획하면 된다.

## 네 임무

**코드를 작성하지 마라.** 오직 계획만 세우고 문서로 정리한다.

1. 저장소 구조와 기존 `/apps/2048/` 구현을 파악한다 (파일을 수정하지는 마라).
2. 픽셀 아트 에디터를 위한 계획을 세운다:
   - 파일 구조: `/apps/pixel-art/` 안에 어떤 파일들을 만들 것인지
   - 캔버스 설계: 16x16 격자를 어떻게 표현할지 (예: `<canvas>` + 픽셀 배열, 또는 CSS Grid의 div
     16x16). 확대해서 그릴 수 있도록 각 셀을 충분히 크게 표시하는 방법도 고려
   - 그리기 상호작용: 마우스 클릭/드래그로 연속 칠하기, 모바일 터치로 그리기, 지우개 기능 여부
   - 색상 팔레트: 기본 제공 색상 몇 개 + 커스텀 색상 선택(`<input type="color">`) 여부 제안
   - PNG 저장: 16x16 그리드를 실제 PNG 파일로 어떻게 변환/다운로드할지 (Canvas API의
     `toDataURL`/`toBlob` + `<a download>` 조합이 프레임워크 없이 표준적인 방법이라는 점을 검토.
     16x16 원본 그대로 저장할지, 확대(업스케일)해서 저장할지도 정리)
   - 전체 지우기(clear) 등 최소한의 편의 기능 검토 (과설계 방지)
   - 스타일: 라이트/다크 모드, 반응형 — 기존 앱들과 통일감 있게
   - 외부 라이브러리 필요 여부 (원칙적으로 최소화, Canvas API만으로 충분한지 검토)
3. 계획을 `/apps/pixel-art/spec.md` 파일로 작성한다. 다음을 포함할 것:
   - 개요
   - 파일 구조 (트리 형태)
   - 각 파일의 역할
   - 캔버스/그리기 로직 핵심 설계 (자료구조, 주요 함수)
   - PNG 저장(export) 구현 방식
   - UI/UX 및 조작 방식 (데스크톱 마우스 + 모바일 터치)
   - Embed 단계에서 무엇을 수정해야 하는지에 대한 메모 (참고: `src/build.js`의 `apps` 배열에
     항목을 추가하면 카드가 자동으로 생기는 구조이므로, 이번엔 build.js의 핵심 로직 자체를
     바꿀 필요는 없을 가능성이 크다 — 실제로 그런지 확인해서 메모에 적을 것)

## 제약

- `/apps/pixel-art/spec.md` 파일만 생성/수정한다. 그 외 어떤 파일도 만들거나 수정하지 마라
  (`/apps/2048/`은 참고용으로 읽기만 하고 절대 수정하지 마라).
- 실제 코드(HTML/CSS/JS)는 작성하지 마라. 이번 단계는 계획 수립까지만.
- 과도한 기능(레이어, undo/redo 스택, 애니메이션 프레임, 클라우드 저장 등)을 제안하지 마라.
  요청 범위(16x16 격자, 팔레트, PNG 저장, 모바일 대응)에 충실할 것.

## 완료 후

작업을 마치면 `/apps/pixel-art/spec.md`가 작성되었음을 요약해서 보고하라.
