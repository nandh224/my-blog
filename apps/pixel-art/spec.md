# 픽셀 아트 에디터 - 계획 문서 (Plan)

> 이 문서는 계획 단계 산출물이다. 실제 에디터 코드(HTML/CSS/JS)는 포함하지 않으며,
> Embed/Build 단계에서 이 계획을 바탕으로 구현한다.

## 1. 개요

`my-blog` 저장소는 마크다운 블로그 외에 미니 웹앱들을 `/apps/` 아래에 포트폴리오 형태로
호스팅한다 (`/apps/2048/`이 이미 같은 방식으로 구현되어 있음). 이번 앱은 **16x16 격자에
도트를 찍어 그림을 그리고 PNG로 저장할 수 있는 픽셀 아트 에디터**다.

- 16x16 격자에서 셀을 클릭/드래그하여 원하는 색으로 칠한다
- 색상 팔레트(기본 제공 색상 + 커스텀 색상 선택)에서 그릴 색을 고른다
- 완성한 그림을 PNG 파일로 다운로드한다
- 프레임워크 없이 순수 HTML/CSS/JS로 구현 (블로그 본체와 동일한 기술 스택 제약)
- `/apps/2048/`과 마찬가지로 자체 완결적(self-contained) 앱이며, 블로그의 `styles.css`를
  재사용하지 않고 전용 CSS를 별도로 둔다. 다만 라이트/다크 모드 대응, "장식보다 콘텐츠(그림)
  우선"이라는 프로젝트 디자인 원칙은 동일하게 따른다

## 2. 저장소 구조 파악 결과 (참고용, 이번 단계에서 수정 없음)

- `src/build.js`: 이미 `/apps/` 디렉터리 전체를 재귀적으로 `dist/apps/`로 복사하는 로직
  (`copyDirRecursive`, `skipExt: [".md"]`)과, 블로그 메인 페이지에 노출할 앱 목록을 담는
  `apps` 배열이 구현되어 있다. 현재 `apps` 배열에는 `{ name: "2048", path: "2048", description: ... }`
  항목 하나만 있다.
- `src/templates.js`: `indexPage(posts, apps)`가 `appsSection(apps)`를 호출해 `apps` 배열을
  순회하며 카드(제목/설명/`<iframe>` 미리보기, `apps/{path}/index.html` 링크)를 자동 생성한다.
  즉 카드 UI를 위해 `templates.js`를 직접 고칠 필요는 없고, `apps` 배열에 항목만 추가하면 된다.
- `.github/workflows/deploy.yml`: `npm run build` 실행 후 `dist/` 폴더 전체를 GitHub Pages
  아티팩트로 업로드한다. `build.js`가 이미 `/apps/`를 `dist/apps/`로 복사하므로 별도 배포
  설정 변경은 필요 없다.
- `spec.md`, `plan-instructions.md` 등 `.md` 파일은 `copyDirRecursive`의 `skipExt: [".md"]`
  옵션으로 `dist/`에 복사되지 않는다 — 즉 계획 문서를 지금 작성해 두어도 배포 결과물에는
  노출되지 않는다.

**결론**: `/apps/2048/`을 추가했을 때와 달리, 이번에는 `build.js`의 핵심 복사 로직(범용 재귀
복사)이 이미 마련되어 있어 그 부분은 건드릴 필요가 없다. Embed 단계에서 필요한 변경은
**`src/build.js`의 `apps` 배열에 pixel-art 항목 하나를 추가하는 것뿐**이다 (8절 참고).

## 3. 파일 구조

```
apps/pixel-art/
├── spec.md          # (본 문서, plan 단계 산출물)
├── index.html        # 에디터 페이지 마크업 (팔레트, 캔버스, 저장/지우기 버튼)
├── style.css         # 에디터 전용 스타일 (라이트/다크, 반응형)
└── editor.js          # 그리기 로직 + 팔레트 + PNG 저장 처리
```

- 외부 라이브러리: **불필요**. 격자 렌더링, 클릭/드래그/터치 입력, PNG 변환 모두 Canvas API와
  순수 JS만으로 충분히 구현 가능한 범위이므로 CDN 라이브러리를 도입하지 않는다.
- 이미지/폰트 등 별도 에셋 없음.

## 4. 각 파일의 역할

### `index.html`
- `<meta viewport>`, 타이틀(`픽셀 아트 에디터`), `style.css` 링크
- 블로그 메인으로 돌아가는 링크 ("← 블로그로", `/apps/2048/index.html`과 동일한 패턴)
- 헤더: 앱 제목 + 간단한 조작 안내 문구(예: "클릭/드래그로 칠하기")
- 팔레트 영역: 기본 색상 스와치 버튼들 + 커스텀 색상 선택(`<input type="color">`) + 현재
  선택된 색 표시
- 그리기 영역: `<canvas id="grid" width="16" height="16">` 하나 (5절 참고)
- 도구 버튼: 지우개 토글, 전체 지우기(Clear), PNG로 저장(Save/Download)
- `<script src="editor.js" defer></script>`

### `style.css`
- `/apps/2048/style.css`와 동일한 패턴(라이트 기본값 + `prefers-color-scheme: dark` +
  `data-theme` 속성 오버라이드)의 CSS 변수 기반 다크모드. 블로그의 `styles.css`는
  재사용하지 않고 이 앱에 필요한 최소 변수만 자체 정의(배경, 텍스트, 팔레트 스와치 테두리,
  버튼 색 등)
- 캔버스: CSS로 실제 렌더링 크기를 확대(`width`/`height`를 CSS에서 크게 지정하고
  `image-rendering: pixelated`로 픽셀 경계를 또렷하게 유지). `aspect-ratio: 1`로 정사각형
  유지, `max-width`로 데스크톱에서 과도하게 커지지 않게 제한, 작은 화면에서는 뷰포트 너비에
  맞춰 축소
- 팔레트: 스와치를 flex-wrap 그리드로 배치, 선택된 색상은 테두리/체크 표시로 강조
- 반응형: 모바일에서 캔버스와 팔레트가 세로로 쌓이고 터치 조작에 방해되지 않도록 버튼/스와치
  크기를 충분히 확보 (최소 탭 타깃 ~40px 권장)
- 애니메이션: 블로그 원칙에 따라 최소화. 선택된 색상 강조 정도의 즉각적인 스타일 변화만 사용

### `editor.js`
- 에디터 상태, 그리기 로직, PNG 저장, 입력 처리를 모두 포함 (규모가 작으므로 `2048/game.js`와
  같이 파일 분리하지 않음)
- 아래 5~7절 참고

## 5. 캔버스/그리기 로직 핵심 설계

### 캔버스 표현 방식
- `<canvas>` 하나를 사용하고, 논리적 해상도는 `16x16`(`canvas.width = 16; canvas.height = 16`),
  CSS로 화면에 보이는 크기만 확대한다(`style.width/height`를 예: `384px`처럼 크게 지정,
  `image-rendering: pixelated`로 확대 시에도 각 셀이 또렷한 사각형으로 보이게 함).
  - CSS Grid로 `div` 256개를 두는 방식도 검토했으나, PNG 저장 시 결국 Canvas API가 필요하고
    (7절), 그리기 상태와 렌더링을 이중 관리(DOM + 별도 배열)하지 않아도 되므로 canvas 단일
    소스가 더 단순하다. 따라서 **canvas + 픽셀 배열** 방식을 채택한다.
- 클릭 좌표를 셀 좌표로 변환할 때는 `canvas.getBoundingClientRect()`로 실제 화면 크기를 구하고,
  `(clientX - rect.left) / rect.width * 16`을 내림해 열 인덱스를, 같은 방식으로 행 인덱스를
  구한다 (CSS 확대 배율과 무관하게 항상 정확한 셀을 짚기 위함)

### 자료구조
- `pixels`: `string[16][16]` (또는 `null` 허용) — 각 셀의 색상값(`#rrggbb`) 또는 미채색 상태.
  미채색은 `null`로 두고 렌더링 시 배경색(투명 또는 체커보드 무늬 대신 단순 배경색)으로 그린다.
  PNG 저장 시 미채색 칸을 투명으로 내보낼지 배경색으로 내보낼지는 6절 참고
- `currentColor`: `string` — 현재 선택된 팔레트 색상 (`#rrggbb`)
- `isErasing`: `boolean` — 지우개 모드 여부 (켜져 있으면 칠할 때 `currentColor` 대신 지움
  처리)
- `isPointerDown`: `boolean` — 드래그 중 연속 칠하기를 위한 상태 플래그

### 주요 함수
- `paintCell(row, col, color)`: `pixels[row][col]`을 갱신하고 해당 셀만 다시 그림
  (`ctx.fillRect(col, row, 1, 1)` — canvas 좌표계를 16x16 그대로 사용하므로 셀 하나가
  `1x1` 사각형)
- `eraseCell(row, col)`: `pixels[row][col] = null` 처리 후 배경색으로 다시 그림
- `renderAll()`: 초기 로드/전체 지우기 시 `pixels` 전체를 순회하며 캔버스를 처음부터 다시 그림
- `cellFromPointerEvent(event)`: 클릭/터치 좌표를 `{row, col}`로 변환 (범위를 벗어나면 무시)
- `clearCanvas()`: `pixels`를 전부 `null`로 초기화하고 `renderAll()` 재호출
- `exportPng()`: PNG 저장 처리 (7절 참고)

### 진행 흐름
1. 페이지 로드 시 `pixels`를 전부 `null`로 초기화하고 배경색으로 캔버스를 채움
2. 포인터(마우스/터치) 다운 → 해당 셀을 `currentColor` 또는 지우개 모드면 지움 처리로 칠하고
   `isPointerDown = true`
3. 포인터가 눌린 상태로 이동(드래그) → 지나가는 각 셀마다 같은 칠하기 처리 (셀이 바뀔 때만
   다시 그려 불필요한 반복 호출 방지)
4. 포인터 업/캔버스 밖으로 나감 → `isPointerDown = false`
5. 팔레트에서 색상 선택 → `currentColor` 갱신, 지우개 모드 자동 해제
6. "지우개" 버튼 토글 → `isErasing` 전환, 활성 시 버튼 강조 표시
7. "전체 지우기" 버튼 → 확인 없이 즉시 `clearCanvas()` (2048의 "새 게임"과 동일하게 과설계
   방지 차원에서 확인 다이얼로그는 넣지 않음)
8. "PNG로 저장" 버튼 → `exportPng()` 호출

## 6. 색상 팔레트

- 기본 제공 색상: 8~12개 정도의 대표 색상 스와치(예: 검정, 흰색, 회색, 빨강, 주황, 노랑, 초록,
  파랑, 보라, 갈색 등)를 버튼으로 나열. 클릭하면 `currentColor`로 지정되고 선택 표시(테두리 등)
  갱신
- 커스텀 색상: `<input type="color">` 하나를 팔레트 끝에 배치해 임의의 색상을 고를 수 있게 함
  (기본 제공 색상 목록에 없는 색이 필요할 때). 값이 바뀌면 즉시 `currentColor`에 반영
- 팔레트 상태 저장(localStorage 등)은 요구사항에 없으므로 구현하지 않음 — 새로고침하면 기본
  팔레트/빈 캔버스로 초기화 (2048의 "새로고침하면 새 게임 시작"과 동일한 방향)
- 미채색 칸의 취급: 팔레트에 "지우개"를 별도 도구 버튼으로 두는 방식을 기본안으로 제안
  (색상 스와치 목록에 흰색이 이미 있을 수 있어 "흰색으로 칠하기"와 "지우기(투명/미채색)"를
  버튼으로 구분하는 편이 사용자에게 명확함)

## 7. PNG 저장(export) 구현 방식

- 방식: Canvas API의 `toDataURL("image/png")` (또는 `toBlob`) + `<a download>` 조합을
  사용한다. 이는 프레임워크/서버 없이 클라이언트에서 파일 다운로드를 트리거하는 표준적인
  방법이며, 별도 라이브러리가 필요 없다
- 원본 그대로(16x16) 저장할지, 확대(업스케일)해서 저장할지: **업스케일해서 저장하는 것을
  기본안으로 제안**한다. 16x16 원본 그대로 저장하면 대부분의 이미지 뷰어/공유 환경에서 파일이
  실제로는 매우 작게 보이거나 흐릿하게(브라우저의 기본 스무딩) 확대되어 표시되는 문제가 있다.
  절차:
  1. 화면에 보이는 16x16 그리기 전용 캔버스와는 별도로, 저장 시점에 임시 캔버스(예:
     `512x512`, 16의 배수인 32px/셀)를 하나 생성한다
  2. 임시 캔버스의 컨텍스트에 `imageSmoothingEnabled = false`를 설정해 확대 시 각 셀이
     흐려지지 않고 또렷한 사각형(픽셀 아트 특유의 각진 느낌)으로 유지되게 한다
  3. `pixels` 배열을 순회하며 각 셀을 `scale x scale` 크기의 사각형으로 임시 캔버스에 그린다
     (원본 16x16 캔버스를 `drawImage`로 그대로 확대해도 되지만, `imageSmoothingEnabled = false`
     조합으로 동일한 결과를 얻을 수 있으면 그 방법도 무방 — 구현 단계에서 더 간단한 쪽 선택)
  4. 임시 캔버스의 `toDataURL("image/png")` 결과를 `<a>` 엘리먼트의 `href`에 설정하고
     `download="pixel-art.png"` 속성을 준 뒤 클릭 이벤트를 트리거해 다운로드한다
  5. 미채색 칸은 투명(alpha 0)으로 내보낸다 — 임시 캔버스를 그리기 전에 `clearRect`로
     비워두면 기본적으로 투명 상태이므로 별도 배경색을 채우지 않는 한 자연스럽게 투명 PNG가
     된다 (에디터 화면에서는 미채색 칸이 배경색으로 "보이지만" 저장되는 PNG에서는 투명으로
     처리해 다른 이미지에 합성하기 좋게 함 — 과도한 옵션 없이 기본값 하나로 고정)
- 업스케일 배율은 고정값(예: 32px/셀 → 512x512 출력) 하나만 두고, 배율 선택 UI 등은
  요구사항에 없으므로 구현하지 않는다 (과설계 방지)

## 8. UI/UX 및 조작 방식 (데스크톱 마우스 + 모바일 터치)

- **데스크톱 마우스**: `mousedown`으로 칠하기 시작 + `isPointerDown = true`, `mousemove`
  중 눌린 상태면 지나가는 셀을 연속으로 칠함, `mouseup`(캔버스 안/밖 모두) 또는
  `mouseleave` 시 `isPointerDown = false`
- **모바일 터치**: `touchstart`/`touchmove`/`touchend`로 동일한 칠하기 로직 공유.
  `touchmove` 기본 동작(스크롤)을 막기 위해 캔버스에 `touch-action: none`(CSS, `2048/style.css`의
  `#board`에도 동일 패턴 존재)과 `event.preventDefault()`를 사용
- 마우스/터치 좌표 → 셀 변환 로직(`cellFromPointerEvent`)을 공유해 중복을 줄인다
  (2048의 키보드/스와이프가 같은 `move()`를 호출하는 것과 동일한 접근)
- **팔레트 선택**: 스와치 버튼 클릭/탭으로 `currentColor` 변경. 현재 선택된 스와치는 테두리
  강조로 표시해 지금 어떤 색으로 그리는 중인지 항상 알 수 있게 함
- **지우개 토글**: 버튼 클릭으로 on/off, 활성 상태는 버튼 스타일(예: 눌린 느낌의 배경색
  반전)로 표시
- **전체 지우기**: 버튼 클릭 즉시 실행 (요구사항 범위상 확인 다이얼로그, undo 등은 넣지 않음)
- **PNG 저장**: 버튼 클릭 시 바로 다운로드 트리거 (파일명 고정 `pixel-art.png`, 별도 파일명
  입력 UI는 과설계이므로 넣지 않음)
- **다크모드**: `/apps/2048/`과 동일하게 시스템 설정 자동 감지(`prefers-color-scheme`)를
  기본으로 지원. 수동 토글 버튼은 필수 요구사항이 아니므로 이번 계획에는 포함하지 않고,
  필요하면 Embed 단계에서 논의
- **레이아웃**: 캔버스가 화면 중앙 또는 상단에 오고, 팔레트와 도구 버튼이 그 아래(모바일) 또는
  옆(데스크톱 넓은 화면)에 배치되는 정도로 단순하게 구성. 별도 반응형 브레이크포인트는
  `2048/style.css`의 `@media (min-width: 500px)` 같은 최소한의 패턴만 참고

## 9. 범위 밖 (이번 계획에 포함하지 않음)

- 레이어, 여러 프레임(애니메이션) 관리
- Undo/Redo 스택
- 그림 저장/불러오기(localStorage에 프로젝트 저장, 클라우드 저장 등) — 새로고침하면 빈
  캔버스로 초기화
- 그리기 도구 다양화(도형 그리기, 채우기(bucket fill), 스포이트 등) — 요구사항은 "도트를
  찍어서 그린다"이므로 단일 셀 칠하기/지우기만 지원
- 격자 크기 변경(16x16 고정), 확대/축소(zoom) UI
- 수동 다크모드 토글 버튼 (시스템 설정 감지만 기본 지원)

## 10. Embed 단계 메모 — 블로그 메인 페이지에서 수정이 필요한 지점

1. **`src/build.js`**
   - `/apps/`를 `dist/apps/`로 복사하는 로직(`copyDirRecursive`)은 이미 범용으로 구현되어
     있어 **수정 불필요**. 확인 결과 이 함수는 `/apps/` 하위 전체를 재귀 복사하며 `.md` 파일만
     제외하므로, `apps/pixel-art/` 디렉터리를 새로 추가하기만 해도 자동으로 `dist/apps/pixel-art/`에
     복사된다
   - 변경이 필요한 부분은 `apps` 배열뿐이다. 아래 항목을 추가해야 한다:
     ```js
     {
       name: "픽셀 아트 에디터",
       path: "pixel-art",
       description: "16x16 격자에 도트를 찍어 그림을 그리고 PNG로 저장",
     }
     ```
2. **`src/templates.js`**
   - `appsSection(apps)`가 `apps` 배열을 순회해 카드를 자동 생성하므로 **수정 불필요**
     (2048 spec.md가 예상했던 "링크 추가" 작업은 이미 `apps` 배열 기반 자동화로 대체되어
     있음을 확인)
3. **`src/styles.css`**
   - 변경 불필요. 에디터는 자체 `style.css`를 사용하는 self-contained 앱이며, 블로그
     인덱스의 카드 스타일(`.app-card` 등)은 이미 2048 카드에 쓰이고 있는 것을 그대로 재사용함
4. **배포 워크플로(`.github/workflows/deploy.yml`)**
   - 별도 수정 불필요. `npm run build`가 이미 `dist/`에 `apps/` 전체를 포함하므로
     `upload-pages-artifact` 단계가 자동으로 함께 배포함

이상으로 계획 수립을 마친다. 실제 구현(HTML/CSS/JS 작성, `build.js`의 `apps` 배열 수정)은
Embed 단계에서 진행한다.
